# 招呼语优化预览与确认

## 目标

在保留原有招呼语生成与发送流程的前提下，把风格优化从“自动改写并直接进入发送”调整为可选、可预览、可人工确认的步骤。

## 配置

- `greeting_style_suggestions`：是否生成优化建议，默认开启。关闭后只生成一版招呼语，不再调用风格优化。
- `greeting_auto_apply_style`：是否自动采用优化版，默认关闭。仅在生成优化建议时生效。

## 状态规则

1. 生成器始终保存原文；有优化结果时同时保存优化版和问题说明。
2. 默认配置下，有两个版本的招呼语进入 `greeting_selection=pending` 状态（岗位仍为 `ready`），页面可预览原文、优化版和问题说明。
3. `pending` 状态不能发送，也不会进入后台发送队列。
4. 用户可以保留原文、采用优化版，或提交不超过 300 字的手工编辑内容。
5. 选择操作必须显式确认；确认后记录选择类型和确认时间。
6. 已人工确认的招呼语不会被后续生成任务覆盖。
7. 开启“自动采用优化版”后，优化版直接进入可发送状态，但仍在页面保留两版内容供查看。
8. 手动编辑保存后，页面展示最终发送版本；编辑和保存期间禁止单条或批量发送。
9. 点击“发送招呼语”只发送当前最终版本，不会再次调用招呼语生成，也不会把岗位退回待确认状态。

## 生成与重生成

- 工作台可为所选岗位单独生成招呼语，任务在后台运行，显示逐岗位进度、错误和暂停原因，支持停止。
- 普通生成保留已有招呼语；详情页的“AI 重新生成”仅替换尚未人工确认的草稿，同时更新原文和优化预览。
- 详情页手动保存与预览卡片确认使用相同的锁定规则。已确认文案如需调整，请手动编辑；AI 重生成不会覆盖。
- 生成期间岗位被修改、删除或状态发生变化时，结果不会覆盖新状态，并报告冲突。

## 接口

- `POST /api/jobs/<job_id>/greeting-selection`
- 请求字段：`selection`（`original`、`optimized` 或 `edited`）、`confirmed: true`；手工编辑时还需提供 `greeting`。
- `POST /api/jobs/<job_id>/greeting`：详情页编辑，需提供 `greeting` 和 `confirmed: true`；记录为人工确认的编辑版本。
- `POST /api/workbench/greetings`：提供 `job_ids`，可选 `regenerate: true`，返回后台任务。
- 未确认、内容为空、内容超长、岗位状态不允许或已发送时，接口拒绝修改。
- 生成、投递、全流程和监测任务运行或停止中时，两个文案修改接口均拒绝操作；检查、保存和任务启动共用互斥锁。

## 发送边界

页面单条发送、批量发送和后台发送队列共用同一状态边界：有优化预览且仍待选择的招呼语不能发送。预览和确认只修改本地岗位记录，不会自行触发对外发送。单独生成的草稿不会在下次启动全流程时被自动发送；发送必须明确选择岗位并通过发送确认。
