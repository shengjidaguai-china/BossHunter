# 智联、前程无忧和猎聘的投递与采集保护

岗位池选中已评分的待确认岗位后，点击“一键投递已选”，人工确认后按来源平台串行执行。BOSS 发送招呼语；智联、前程无忧和猎聘点击职位详情页的申请按钮，51job、猎聘使用网站现有默认简历。智联可配置 `platforms.zhilian.delivery.resume_name` 为已确认附件的精确文件名：唯一匹配的 PDF 会自动选中、勾选默认并提交，不上传或选择其他未知简历。

投递前核对 HTTPS 域名、来源岗位 ID、详情标题、公司和唯一可见申请按钮。登录、验证码、未指定或不匹配的简历、问卷、付费提示或不明确弹窗需要人工处理。点击前在本地历史中提交 `delivery_attempt`；智联最终提交前另记 `delivery_submit_attempt`。明确成功提示或提交后连续两次稳定的“已投递”状态才记为 `sent`。结果不明时保留页面、停止队列，重启或次日也不会自动重复提交；只有重新人工确认、已知仅停在智联简历选择且未记录最终提交尝试时，才允许从原弹窗继续或重新打开详情。重新打开详情仍须核对岗位身份，且不能再次预留同一申请意图；在原平台确认已经成功后，可使用原有“手动标记已发送”功能。

三个平台均在 `platforms.<平台>.safety` 配置独立额度：

| 配置 | 默认值 |
| --- | ---: |
| `daily_search_page_limit` | 20 |
| `daily_detail_page_limit` | 50 |
| `daily_platform_page_limit` | 80 |
| `daily_delivery_limit` | 10 |

搜索 API 请求、API 宿主页与 DOM 搜索导航均计入搜索额度；详情尝试计入详情额度；采集和投递共用该平台的总访问额度。访问失败也消耗已预留额度。计数保存在数据库，重复启动不会重置。采集保持既有操作间隔和退避；投递复用全局发送窗口、随机间隔、休息日和总日额度，结果不明的投递尝试也计入总额度。

验证码、限流或连续失败停止任务并设置共享持久冷却锁；没有可用统计数据库时停止，不进行无记录访问。额度用完只停止该平台采集，风险信号停止整条队列。这些设置减少访问压力，不保证账号不会受限，也不绕过验证码或平台限制。

三个平台不支持聊天监测、自动回复或聊天内追加简历，因此含监测的“全流程”仍仅适用于 BOSS。页面变化会导致安全暂停，需要更新适配器后重新核验。

验证边界：离线测试覆盖成功回执、误匹配、验证码、限流、模态框、不明结果、跨日防重复、额度和取消；真实详情页面只读检查不等同于真实投递成功。未经岗位级确认不进行实机提交。
